# l10n-incremental · 增量更新与交付签发

> **职责**：流程的出口。管两件事：改稿时**不全量重译**（37 段的活别当 1286 段干），交付时**如实声明**质量保证范围。

## A. 增量路径（客户改稿时）

**先算账再动手**：
```bash
python scripts/incremental.py <新中文.docx> <旧中文.docx> wk/overrides
```
输出待译段/孤儿条目。**待译段 = 本轮全部翻译范围**，其余沿用已有 override（人工裁决过的段落白不做是最大浪费）。

| 路径 | 场景 | 要点 |
|---|---|---|
| **A 英文侧改动** | 客户只改了两节 | 只翻待译段 → build_override 合并 → merge 重建链 → qc + 回译改动段 + **改动段过 `l10n-review`** |
| **B 中文源被裁决修订** | 补字/改表述 | override 键=中文原文，**键必须跟随源文同步改**（同段多批次一起改），否则 merge 未命中→中文残留；中文 docx 保格式直改（三安全阀：命中数≠预期立即停/全文档 xmlns 注册/独立重开对账） |

改动段的表达层验证不可省——增量不是免检通行证，只是缩小范围。

## B. 交付签发（出口）

签发前置：`l10n-accept` 的签发卡已签字（交互点 5）。

**交付前 checklist（终审，逐项打勾）**：
- [ ] 结构五项与源文件全同；QC 五项全绿
- [ ] 术语合规 ≥90% 且剩余报警逐条核过
- [ ] 每节回译对账跑过；合并后全篇可疑段 <10% 且逐条可解释
- [ ] 润色三项对账通过 + 改动段回译复检
- [ ] 合并链四步齐全，Word 实开无「另存」弹框
- [ ] 表格行不跨页、跨页重复表头（抽查两三张长表）
- [ ] **表达层：上岗证书有效（rubric-hash 与当前 rubric 一致，判定报告带 doc sha256 与证书）+ 抽检判定通过 + 交互点 1-5 全走完**
- [ ] 缺陷台账已记录本稿数据
- [ ] 不确定列表已全部作答；源稿问题清单已反馈客户

**交付声明（如实描述质量保证范围，含表达层升级版）**：

> 本译文经机器全量检查（结构/数字/术语/体例）、回译对账与全篇润色；表达层经校准后的独立评审会话按定版 rubric（vN，hash 见附件）逐段评分，并按分层抽样（约 X%，Y 段）抽检验收（critical 0 处，major Z 处/千词）。以上为 AI 辅助质量保证，未由第二人对照原文全文通读；术语与体例依据 IWA/AWWA/Ofwat 及客户既定口径。

**为什么这么写**：含糊说「已检查」而实际没通读才是问题；如实声明不是免责，是准确描述（既有 standards 文档纪律的延续）。

## 红线

- 增量改动段必过表达层评审（A 路径最容易被「只改了一点」麻痹）
- 交付声明里的每个数字（抽样数/缺陷密度/rubric 版本）从工具产物抄，不许手填
- 签发未完成，交付物不出工作区
