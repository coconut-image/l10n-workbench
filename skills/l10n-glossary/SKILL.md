# l10n-glossary · 术语表构建与溯源

> **职责**：产出项目工作区 `glossary/`，覆盖中文稿 ≥95% 专业词。术语不是「译」出来的，是「溯源」回来的——目标读者用哪套文献，术语就跟哪套。
> **上游**：总纲阶段 0（结构体检已过）。**下游**：阶段 1-4 翻译、`l10n-sediment` 沉淀。

## 开工 checklist

- [ ] 结构体检已过（章节能定位）
- [ ] 项目工作区 `wk/glossary/` 已建（扁平 md，文件名前缀定加载序：`10_` 行业 → `20_` 项目 → `30_` 客户）
- [ ] 现有术语表已清点（往期项目直接继承）

## 流程四步

### 1. 溯源建表（S 层——行业标准）
按目标读者文献逐条查英文原生写法：IWA（leakage、District Metered Area）、AWWA M36（ILI/UARL）、Ofwat（minimum night flow）。**只收录有出处的**，条目带依据列（S/P/C）。国内标准只作对照，不作英文依据。

### 2. 高频词扫描补缺口（P 层）
```bash
python tools/freq_scan.py <中文.docx> --glossary wk/glossary --min 5
```
输出「出现 ≥5 次、术语表未收录」的候选词清单。逐个人工定译法（溯源优先，无标准则按行业惯用），追加进 `20_项目_*.md`。

### 3. 客户专名（C 层）
机构名、编号、保留原文项从客户既有文档（往期报告/官网/系统界面）抄录，含写法口径规则（如「首次全称其后缩写」）。

### 4. 覆盖率检查（操作定义）
用 freq_scan 再跑一遍：`--min 5` 下候选清单为空 + 人工抽核若干出现 <5 次的低频专业词 → 覆盖达标，放行翻译。（总纲阶段 0.5 的「≥95%」按此操作定义执行——出现不足 5 次的专业词不在扫描口径内，靠人工抽核补位。）

## 交互点 · 术语冲突裁决

**触发**：两层表对同一概念给出不同译法、或源稿用词与术语表冲突。
**你必须做**：停下来，向用户呈结构化选项——每条形如「『漏損定位』：A `leak localisation`（IWA 惯用）vs B `leakage positioning`（客户往期报告用法）——请选」，**不要自作主张替用户选**。
**记录**：裁决结果进决策记录（`wk/decisions.json`，供 `l10n-sediment` 回填），格式必须含 `kind` 字段（回填工具按它分流，**缺 kind 的条目会被整批拒写**）：`{"kind": "term", "term_zh":…, "chosen":…, "rejected":…, "reason":…, "date":…}`。

## 升格规则（provisional → 正式）

- 单次裁决进表时标 `provisional`（第 4 列注记）
- **同类裁决出现第二次** → 升格为正式条目（去掉 provisional）
- 正式条目改动 = 术语表版本升级，须回扫已定稿内容

## 红线

- **边跑边补是应急不是常态**：连续两节要补表 → 停下重做本流程（教训出自实测：可疑率跳高根因都在术语表）
- 长词优先匹配（漏損定位 先于 漏損）；「用法」列区分表格锁/正文放开——详见既有 `glossary-schema` 文档（随包分发）
- 只增不改（与上游冲突以上游为准）；本表不收纯拉丁/数字条目
